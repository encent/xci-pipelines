# Configuration

Everything lives in `config/config.yaml`. `bash configure.sh` walks you through
the parts you must change; this file explains the rest.

If you are reproducing the paper on the machine the analysis was done on, the
shipped defaults are already correct and you can skip to
[Running a subset](#running-a-subset).

---

## The three things you must set

### `paths.data_dir`

Where everything the pipeline produces goes. Needs roughly **500 GB** free for a
full run. Nothing is ever written outside this directory (plus the two satellite
conda environments).

```yaml
paths:
  data_dir: /scratch/you/xci-pipeline-data
```

### `paths.inputs`

Where *your* data already is. **These are read-only to the pipeline** — the only
operation performed on them is `ln -s`. It never writes to, moves, or modifies
your input files.

```yaml
paths:
  inputs:
    bam_dirs:
      H3K27me3_WT:   /path/to/wt/h3k27me3/bams
      H3K27ac_WT:    /path/to/wt/h3k27ac/bams
      CTCF_WT:       /path/to/wt/ctcf/bams
      degron_all:    /path/to/degron/bams
      RNAseq_WT:     /path/to/wt/rnaseq/bams
      RNAseq_degron: /path/to/degron/rnaseq/bams
    cooler_dir:      /path/to/coolers
```

BAMs must be allele-split, with one unsplit (`Gall`) file per library alongside
its `Xa` and `Xi` splits — the three share a single normalisation factor.

### `config/samples.tsv`

Generated by `install.sh` from your metadata sheet. One row per file. Set
`use=false` to drop a sample without deleting the row. Sample IDs must follow
`{mark}_{clone}_{condition}_{allele}_rep{n}` — the pipeline validates this at
startup and tells you exactly which row is malformed.

## Chromosomes — two independent sets

```yaml
chromosomes:
  csaw:       [chr2, chr3, chr4, chr5, chr7, chr8, chr9, chr10,
               chr13, chr14, chr15, chr17, chr18, chr19]
  downstream: [chrX]
```

**These are deliberately separate and must stay so.**

`csaw` controls which chromosomes the TMM normalisation factors are estimated
from. **chrX is excluded on purpose**: one X is inactivated, and *which* parental
X differs between clones, so including it would make the factors reflect
X-inactivation rather than library size. The pipeline refuses to start if you add
chrX here.

`downstream` controls everything else — valleys, Hi-C, METALoci, figures. Narrow
it to test quickly; widen it for a full analysis.

## Determinism

```yaml
valleys:
  blas_threads: 2
```

The valley caller fits a Gaussian HMM whose k-means seeding is sensitive to how
many threads the numerical libraries use, so **the same input can otherwise give
different valleys on different machines**. This pins it.

`2` is the shipped value for two reasons: it agreed with the published calls on
more tracks than any other setting tested, and it is the only value honourable on
a two-core machine — `threadpool_limits` sets a *ceiling*, so a larger value
silently becomes something smaller on modest hardware, which is exactly the
nondeterminism being eliminated.

The observed thread count is recorded in `results/provenance.json`. Hi-C and
METALoci are deliberately **not** pinned (`hic.blas_threads: null`) because they
already reproduce exactly at any thread count, and pinning them could only
perturb a result that is currently correct.

## Reproduction switches

```yaml
legacy:
  h3k27ac_positional_scalefactors: false
```

The original analysis assigned normalisation factors to allelic splits
*positionally* rather than by matching sample identity. In one run that had an
odd number of input files, this mis-assigned five H3K27ac tracks.

* `false` (default) — assign factors by matching `(mark, clone, condition,
  replicate)`. **Correct.**
* `true` — reproduce the original assignment exactly, including the five
  mis-assigned tracks, so published outputs can be byte-compared.

Use `true` only to verify against the original files; use `false` for any new
analysis.

```yaml
normalization:
  scale_factor_source: compute      # compute | fixture
```

`compute` estimates normalisation factors from your BAMs. `fixture` injects
pre-computed factors from `resources/fixtures/scalefactors/`, which is what makes
a single-chromosome test possible — the factors cannot be estimated from one
chromosome, but everything downstream of them can be checked against it.

## Loci

```yaml
loci:
  Mecp2:
    chrom: chrX
    regions:
      non_escape: [73315000, 73645000]
      escape:     [73645000, 74475000]
      full:       [73315000, 74475000]
```

The regions analysed, in genome coordinates. `Jarid` is the internal name for
**Kdm5c**; `loci.display_names` maps internal names to the labels used in
figures. Add a locus here and it flows through the contact-map, compartment and
METALoci stages automatically.

## Running a subset

```bash
./run.sh dryrun      # show what would run, change nothing
./run.sh demo        # small end-to-end run, ~2 h
./run.sh signal      # normalisation and coverage tracks only
./run.sh valleys     # H3K27me3 valley calling
./run.sh contacts    # contact-map preparation
./run.sh hic         # loops, compartments, METALoci
./run.sh figures     # the visualisation stage
./run.sh             # everything
```

Targets pull their own prerequisites, so `./run.sh valleys` will build whatever
normalisation it needs first. Nothing is lost on failure — re-running resumes.

Optional quality-control outputs (FastQC, fragment sizes, peak calling, FRiP)
are off by default; enable with `qc.enabled: true`.

---

## Resources

```yaml
resources:
  max_threads: 48
  max_mem_mb: 120000
```

Defaults suit a large workstation. Lower them for a laptop; the pipeline will
schedule fewer jobs concurrently rather than failing. Per-rule requirements are
declared in the rule files and can be overridden through a Snakemake profile in
`profiles/`.
